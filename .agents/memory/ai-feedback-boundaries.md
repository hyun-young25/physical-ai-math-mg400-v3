GPT는 한국어 단계별 질문·힌트와 예측/결과 비교만 맡는다. 기존 수학 판정·좌표 계산·안전 검사·학생의 실제 실행 승인은 AI 문장과 무관하게 유지한다.

**Why:** 사용자가 맞춤 피드백을 요청하면서 AI의 채점 변경·이동 명령·확인되지 않은 실측/집기 성공 추정을 명시적으로 금지했다.

**How to apply:** 새 과제에 AI를 붙일 때도 실행 지원 범위를 늘렸다고 암시하지 않는다. 차단/취소/오래된 값은 수학 오답이나 성공으로 바꾸지 않는다. API 장애는 학습·실행을 중단시키는 근거가 아니다.

운영자의 OpenAI 키만 Replit Secrets에서 서버가 사용하며 학생 개인 키는 요구하지 않는다. AI에는 불필요한 학생 식별·연락 정보를 보내지 않는다. 최초 예측·풀이를 수정 답으로 덮어쓰거나 과거 기록에 AI 활동을 소급 생성하지 않는다.

**Why:** 사용자가 운영자 비용/키 관리와 학생별 연구 기록의 원본·출처 보존을 요구했다.

**How to apply:** 제공/미제공 상태와 실제 힌트 문장을 구별한다. 가상·시험용·실측 출처를 유지하며 실장비 없는 시험과 실제 API 검증 여부를 각각 보고한다.

대화형 튜터에서는 창에 실제 표시된 힌트와 후속 질문만 제공 활동으로 남긴다. 접힌 창의 미확인 응답과 늦게 도착해 폐기한 응답은 제공 이력에 포함하지 않는다.

**Why:** 사용자가 실제로 받은 힌트와 후속 질문만 기록하며 최초 예측과 기존 기록을 보존하도록 명시했다.

**How to apply:** 같은 문제의 실제 제공 대화만 후속 맥락으로 쓰고, 단원·문제·답안 전환 시 요청과 판정의 유효성을 따로 확인한다.

공개 게시·재게시를 진행하지 않는다. 이전 재배포 승인과 실제 GPT 성공 후 자동 재배포 요청은 취소되었다. 기존 공개 사이트를 삭제하거나 중지하지 않는다.

**Why:** 사용자가 개발 미리보기에서 구현·작동만 원한다고 범위를 명확히 수정했다.

**How to apply:** 이번 작업과 후속 자동 작업에서 배포하지 않는다. 실제 GPT 성공·크레딧 충전을 구현 완료의 선행 조건으로 삼지 않는다. 외부 AI 호출 없는 체험 모드를 기본으로 제공하고 실제 GPT 연동은 유지한다. UI 시험 성공과 실제 서비스 성공을 분리해 보고하며 비밀 설정·결제 변경은 포함하지 않는다.

## 제출 기반 자동 피드백

질문하지 않아도 객관적으로 채점 가능한 문항의 기존 제출·예측 비교 판정에 따라 기존 챗봇에 힌트를 제공한다. 입력 중에는 반응하지 않는다. 첫 오답에는 답을 직접 공개하지 않는 구체적인 힌트, 같은 문항의 재오답에는 계산·개념 설명, 수정 정답에는 올바르게 고친 점을 안내한다. 교사 확인용 자유 서술이나 로봇 연결·범위·실행 실패는 수학 오답으로 취급하지 않는다.

**Why:** 사용자가 2-1·2-2부터 제출 기반 피드백을 요구하면서 AI의 정오 추측, 첫 오답의 정답 공개, 중복 제출·다른 과제의 늦은 응답 혼입을 금지했다.

**How to apply:** 자동 힌트는 기존의 명시적인 객관적 판정을 읽는 규칙 기반으로 즉시 제공하여 외부 응답 장애에도 유지한다. 직접 질문의 GPT 경로는 별도로 보존한다. 재시도·중복 식별은 방문·문항·제출별로 구분하고, 닫힌 창에는 새 피드백 알림·미리보기를 제공한다. 자동 진행 직전의 수정 피드백은 이전 문항의 결과임을 분명히 표시하며 새 문항 판정으로 바꾸지 않는다. 원본 학습 기록과 실행 승인 절차를 보존하며 실물 없이 검증한다.

실제로 표시한 자동 힌트도 후속 질문의 앞선 대화에 포함한다. 판정 자료의 보강이나 DT 실행 결과 저장은 학생의 새 제출이 아니며, 같은 제출을 여러 번의 오답 시도로 세지 않는다. 반복 오답과 추가 질문은 앞서 제공한 설명에서 계산·역산·입력 적용으로 진전시킨다.

**Why:** 사용자가 같은 문구 반복을 보고하며 단순 문구 숨김이 아닌 제출 처리·요청·응답 맥락의 원인 수정을 요구했다.

**How to apply:** 제출 식별과 판정 내용을 혼동하지 않는다. 상태 갱신만으로 새 피드백이 생기지 않는지, 제공된 자동 힌트와 이전 문답이 실제 후속 요청에 포함되는지 확인한다. 명시적 체험·기본 모드는 이번 질문을 먼저 다루며 빈 풀이를 이유로 같은 일반 힌트만 반복하지 않는다.

실제 GPT 모드의 API 실패는 수학 기본 답변으로 대체하지 않고 원인별 짧은 미응답 상태로 표시한다. 제공자 한도·잔액, 일시 요청 제한, 앱 자체 제한, 인증, 네트워크와 응답 형식을 구분한다. 실패 안내는 학습 설명의 후속 대화 맥락에 섞지 않는다. 운영자만 상세 상태·조치 방법을 조회하며 상태 조회 자체는 유료 API를 호출하지 않는다.

**Why:** 사용자가 실제 GPT를 선택했는데도 같은 기본 안내와 모호한 사용량 제한만 보이는 문제를 보고했다. 기존 허용 범위 내 호출만 허용하며 지출 상한 증액이나 유료 구매를 금지했다.

**How to apply:** 원본 제공자 오류·자격 증명은 화면·응답·로그에 내보내지 않는다. 한도 부족을 이유로 다른 과금 경로나 모델에 임의 전환하지 않는다. 실제 호출 시도, 성공 응답, 모의 검증을 구분하고 외부 설정 때문에 성공을 확인하지 못했으면 분명히 보고한다. 짧은 값 확인 질문도 현재 문항·입력·기존 판정을 활용하고, 명시적 풀이 요청은 현재 문항의 수치 계산과 이유를 설명하도록 한다.
