---
name: 임베디드 미리보기 브라우저 검증
description: 컨테이너의 public-test-parent → loopback 미리보기를 Chromium LNA 정책이 차단하는 이유.
---

컨테이너에서 가짜 공개 부모 페이지에 개발 미리보기를 iframe으로 넣으면 Chromium의 Local Network Access 정책이 실제 앱 로딩 전에 연결을 차단할 수 있다. 이는 앱의 쿠키나 인증 실패와 구별해야 한다.

**Why:** 공개 테스트 도메인에서 컨테이너 내부 loopback으로 해석되는 미리보기 주소를 요청한 결과, 브라우저가 `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS`를 반환했다.

**How to apply:** 이 합성 테스트의 브라우저에서만 LocalNetworkAccessChecks를 제외한다. 앱의 인증·CORS·CSRF·소유자 권한이나 배포 설정을 완화하지 않는다.

독립 HTML에서 실제 앱 컴포넌트를 가져오는 재현 시험은 Vite의 모듈 변환과 HMR 경로를 고려한다. 사전 번들 CommonJS 파일을 원시 URL로 import하면 내보내기가 default 객체에 있을 수 있다. HMR 쿼리가 다른 Provider 모듈을 함께 가져오면 React 컨텍스트가 분리될 수 있다.

**Why:** 재현 환경에서 내보내기 형식과 Provider 모듈 중복 때문에 앱 자체의 오류처럼 보이는 실패가 발생했다.

**How to apply:** 독립 시험의 import 형식과 동일한 Provider 모듈 사용 여부부터 확인한다. 소스 변경 뒤 재현 환경을 구성할 때는 정리된 개발 서버 모듈 그래프를 사용하고, 인증이나 앱 동작을 변경해 시험 오류를 우회하지 않는다.

개발 미리보기는 앱 위에 별도의 안내 배너를 삽입할 수 있으므로, 하단 도킹 UI의 남는 높이는 학생 헤더 높이만이 아니라 앱의 실제 뷰포트 시작 위치를 기준으로 계산한다.

**Why:** 미리보기 배너가 추가한 높이를 빼지 않으면 모바일 학습 영역이 하단 튜터와 겹친다.

**How to apply:** 앱 영역의 실제 위치를 측정하고 화면 크기·상단 영역 변화에 맞춰 갱신한다. 공개 화면에 개발 배너가 있다고 가정하지 않는다.

개발 배너의 ID만으로 요소를 찾으면 같은 ID를 가진 주입용 script가 먼저 잡혀 높이가 0으로 측정될 수 있다. 배너 공간은 앱/학생 헤더의 실제 시작 위치로 판단한다.

**Why:** 키보드 가시 영역을 줄인 시험에서 배너 높이를 0으로 잘못 측정해 튜터 닫기 버튼이 실제 배너 뒤로 숨었다.

**How to apply:** 배너의 특정 DOM 구조나 ID에 의존하지 않는다. 가시 사각형 검사 외에 실제 클릭도 확인해야 높은 레이어의 가림을 발견할 수 있다.

Playwright의 브라우저 내부 WebSocket 모의 브리지는 컨텍스트를 닫아도 Node의 주기 발행 타이머가 남을 수 있다. 모의 연결의 종료 통보에만 정리를 맡기지 않는다.

**Why:** 모든 브라우저 검증 결과가 출력된 뒤에도 검사 프로세스가 남아 묶음 명령이 시간 초과됐다. 앱의 실행 실패가 아니라 모의 브리지 타이머 정리 문제였다.

**How to apply:** 다중 컨텍스트 검사에서는 컨텍스트 교체 및 최종 종료 시 모의 브리지 타이머를 명시적으로 해제하고, 단언 통과뿐 아니라 셸 종료 코드도 확인한다.
