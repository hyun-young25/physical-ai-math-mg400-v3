---
name: Vite 브라우저 검사 fixture의 모듈 경계
description: 수동 동적 import의 CommonJS 호환 문제를 앱 자체 오류와 구분한다.
---

Vite가 최적화한 CommonJS 의존성을 검사 페이지에서 직접 동적 import하면 이름 있는 export 대신 default 아래에 API가 있을 수 있다. 정상 앱의 정적 import는 Vite의 호환 변환을 거치므로 검사 fixture의 빈 화면만으로 앱 회귀라고 판단하지 않는다.

**Why:** 운영자 상태 카드 자체는 정상인데 검사 페이지의 모듈 경계 때문에 초기 렌더가 실패하여 기능 검사가 반복해서 시간 초과되었다.

**How to apply:** fixture 초기 렌더의 브라우저 오류를 먼저 확인하고, 수동 import 결과의 실제 export 형태를 처리한다. 정상 앱 경로의 검사와 fixture의 모듈 부트스트랩 검사를 구분한다.

로봇 실행을 검사하는 React fixture는 정지·실행 종료 콜백의 참조 안정성을 실제 앱과 맞춘다. 프레임마다 새 콜백을 만들면 실행 정리 effect가 반복 호출되어 정상 DT 애니메이션도 중단된 것처럼 보일 수 있다.

**Why:** 격리 검사에서만 DT가 즉시 멈췄고, 실제 원인은 로봇 수학이나 실행 코드가 아니라 fixture가 매 렌더마다 바꾼 콜백 참조였다.

**How to apply:** 실행이 이유 없이 중단되는 격리 검사에서는 먼저 정리 effect의 의존성과 fixture의 콜백 참조를 확인한다. 이를 해결하려고 실제 앱의 정지·취소 안전장치를 약화하지 않는다.
