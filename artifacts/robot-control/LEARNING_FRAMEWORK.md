# 학습과정과 기록의 대응

기준: 박사논문의 7단계 순환(과제 이해 → 수학 구조화 → 표현·예측 → 실행·측정 → 지각·표상 → 비교·해석 → 수정·재실행). 이 문서는 구현 범위와 기록의 의미를 설명하며 교육적 효과의 검증을 뜻하지 않는다.

| 연구 단계 | 콘텐츠의 활동 | 확인할 기록 |
| --- | --- | --- |
| 1. 과제 이해 | 바뀌는 조건·유지 조건, 출발점·목표점 파악 | 문항·조건·출발점 |
| 2. 수학 구조화 | 좌표·변화량·관계식·이동 조건으로 문제 구조화 | 수학 관계, 단위, 적용 조건 |
| 3. 표현·예측 | 좌표·변화량·명령·예상 결과와 근거 입력 | 최초 제출, 시각, 수학적 설명 |
| 4. 실행·측정 | 학생 명령으로 DT 실행, 도형 과제의 선택적 실장비 실행 | 명령, 시작 위치, 실행 상태 |
| 5. 지각·표상 | DT 도착점·궤적·장비 보고 좌표·가상 센서 값 확인 | 출처별 결과, 관찰값, 중지·실행 불가 구분 |
| 6. 비교·해석 | 예상–결과–목표 비교, 절대·상대 표현과 오류 원인 설명 | 설명, 판단 변경, 오류 유형 |
| 7. 수정·재실행 | 수치·근거 수정, 같은 조건 재검증, 새 조건 독립 적용 | 최초 답을 보존한 후속 시도, 근거, 재실행 |

2-1·2-2의 세 묶음 화면은 1–3 / 4–5 / 6–7에 대응한다. 도형 과제의 기존 내부 상태 1–7은 위 7단계에 맞춰 표시한다. 내부 상태를 유지하여 기존 명령·초기화·완료 로직은 바꾸지 않는다. 학습이 이미 성립한 경우 불필요한 수정·재실행을 요구하지 않는다.

## 2-2 대표 과제

1. 절대·상대 개념을 익힌 뒤 같은 가상 물체를 두 방식으로 운반한다.
2. 두 방식의 명령·출발·결과를 비교하고 학생 자신의 설명을 저장한다.
3. 첫 운반 과제는 물체 윗면 Z=20에서 목표 Z=60으로 이동하며, ΔZ=40을 절대좌표·상대좌표 두 방식으로 실행한다.
4. 비교 뒤 새 조건에서는 출발 높이를 Z=30으로 바꾸고 목표 Z=60을 유지한다. 학생은 절대 Z=60과 상대 ΔZ=30을 실행 전에 다시 예측하고, 처음 답·수정 근거·DT 결과를 함께 비교한다.
5. DT의 실제 표시 FK 결과를 기록한다. 한 방식만 실행했거나 중지·거부된 실행은 완료로 처리하지 않는다. 오류가 있으면 수정 근거와 새로운 시도를 남긴다.
5. 설명 저장과 두 방식의 목표 도착이 충족되면 다음으로 진행한다. 서술 내용의 타당성을 자동 채점하거나 개념 이해가 입증되었다고 표시하지 않는다. 교사가 설명을 검토한다.

`transferLearningRecords`는 기존 물체 운반 기록과 분리된다. `pairId`로 두 운반 기록과 연결되며 설명 이력·모든 예측·실행 상태·수정 근거를 보존한다. 목차 이동·초기화·연결 변경 후에도 App 세션 내에서 유지한다. 기록을 내려받기 전에 새로고침하면 이 세션 기록은 사라질 수 있다.

## 지원·데이터 출처

- 현 구현의 학습 힌트·보충은 사전 규칙에 따른 지원이다. AI 모델의 추론·진단을 구현했다고 표현하지 않는다. 기존 로그의 `aiHintCount` 등 키는 호환성을 위해 유지하되 `supportProvider: rule-based`로 출처를 명시한다.
- `math`: 주어진 수치 문제의 수학적 확인값. 로봇 실행·센서 측정과 구분한다.
- `dt`: 모델 계산 결과. 실제 위치 측정이 아니다.
- `virtual`: 사전 생성한 가상 센서 연습값. 물리 장비의 오차나 성능을 입증하지 않는다.
- `hardware`: 연결 장비가 보고한 텔레메트리 좌표. 독립적인 외부 위치 측정과 구분한다.
- 2-1·2-2 JSON 내보내기와 도형 기록에 `schemaVersion`, 공통 익명 `sessionId`, `dataSource`, `supportProvider`, 7단계 정의·대응을 추가한다. 기존 필드는 보존한다. 도형 기록은 기존 브라우저 저장 방식과 최대 100개 제한을 유지한다.

이 메타데이터는 서로 다른 기록의 해석을 맞추기 위한 기반이다. 전 단원 서버 영구 저장, 학습자별 통합 관리, 모든 시각화 클릭·체류시간 수집, AI 적응 지원의 실증은 이번 구현 범위에 포함하지 않는다. 현장 연구에서는 별도 수행평가·관찰·면담과 함께 해석해야 한다.

`MathInquiry`는 단원별 최초 예측·근거, 조건 스냅샷, 각 실행의 시작·종료 시각과 상태, 후속 설명을 보존한다. 후속 시도는 `previousId`와 `attemptKind`로 최초·같은 조건 수정·새 조건을 구분한다. 실행을 재시도하면 같은 동작의 최신 상태를 사용하며 중지된 동작을 과거 성공으로 대신하지 않는다. 원래 답이 맞아도 설명을 저장할 수 있으며, 수정·재실행을 강요하지 않는다. 단원 이동은 자유롭고, 수치 일치나 설명 저장만으로 개념 이해를 자동 판정하지 않는다.

`MathInquiry` 기록은 브라우저 저장소에 백업하며 새로고침 후에도 단원별로 내려받을 수 있다. 진행 화면을 자동 복구하거나 실행을 재개하지는 않는다. 새로고침은 새 익명 세션으로 구분하며 이전 세션을 같은 학습자의 후속 시도로 자동 연결하지 않는다. 2-1·2-2의 App 기록은 앞서 설명한 현재 실행 세션 범위를 유지한다. 학습자별 서버 집계는 구현하지 않는다. 사각형 자기 설명은 기존 브라우저 이벤트 저장소를 사용하며 자동 정오 판정은 `null`이다. 기존 최대 100개 보존 정책을 따른다.

삼각형·원 표의 기준값은 명령 좌표에서 구한 수학적 값이며, 실행 궤적의 실제 길이·실측 오차를 뜻하지 않는다. 별도의 `observedPath`와 `observed`는 동일 DT 모델의 FK 값이다. 원의 기존 경유점 반올림, 충돌 모델의 부재, 실제 관절 제한은 그대로이며 물체 운반 성공이 실장비 안전성이나 학습 효과의 증거는 아니다. 새로운 활동은 DT 전용이고 연결 중 실행·늦은 애니메이션을 차단한다. 도형·종합과제 종료 시 남은 좌표 버퍼를 비워 최종 FK 표시값을 유지한다.


## 수학적 피드백을 실행과 다시 연결하기

- **예측 보존 → 관찰 → 관계 재판단:** `MathInquiry`는 최초 답을 덮어쓰지 않고 `answerReviews`에 피드백 후 판단을 남긴다. 각 재판단은 `runCount`로 그 실행 묶음에만 연결된다. 중단·재실행 후 과거 정답으로 새 실행을 통과시키지 않는다.
- **오류에 맞는 질문 → 선택적 관계 힌트:** 단원·항목별로 부호, 위치와 변화량, 보간 대상, 링크 투영, 모델의 해와 실측 정확도를 구분한다. 힌트 열기와 재판단은 `feedbackEvents`로 기록한다. 규칙에 따른 항목별 지원이며 원인을 확정하는 AI 진단이 아니다.
- **수치 확인 → 자기 설명 → 새 조건:** 처음 맞혔으면 수정 없이 설명할 수 있다. 차이가 난 판단은 결과를 근거로 바로 재확인할 수 있어 불필요한 로봇 재실행을 요구하지 않는다. 단, 명령 자체를 바꾸거나 실행 증거가 없으면 다시 실행해야 한다. 새 조건은 예측을 비우고 힌트를 접어 시작한다.
- **작업 목적에 맞는 수학적 선택:** 2-3은 직선 도포 작업에서 MoveL을 선택하는 이유와, 끝점만 지정한 작업에서 두 방식 모두 가능한 이유를 비교한다. MoveJ가 항상 곡선이라는 오개념을 만들지 않고 현재 궤적을 확인한다. 조건 변경 활동은 직선 제약 유무까지 바꾼다.
- **절대·상대의 잘못된 기준 확인:** 2-2 들기 과제는 실제 DT 출발 높이, 학생의 명령, 도착 높이와 목표의 차이를 연결해 다시 계산할 관계를 안내한다. 중단된 움직임으로 오개념을 판정하지 않는다.

확인값이 제시된 뒤의 정답은 독립 수행의 증거로 사용하지 않는다. `prediction`·`reason`과 `answerReviews`, 힌트 사용, `changed-condition`의 첫 제출을 분리해서 분석한다. `reflections.review=teacher`는 교사 검토가 필요한 응답이라는 뜻이며 검토 완료를 뜻하지 않는다. 문자열이 입력되었거나 수치가 일치했다는 이유로 설명의 질·개념 이해를 자동 채점하지 않는다.

## 측정 피드백 순환

사각형의 완료 측정마다 `MeasurementReview`를 저장한다. 기존 원시 측정 기록과 동일한 `id`를 사용한다. 학생은 어느 점·축을 근거로 어떤 가설을 확인할지, 다음 확인 방법, 재측정 RMSE 예상 방향을 적는다. 계획 저장은 장비 명령을 보내지 않는다. 실제 실행에는 기존 DT 검증·연결·초기화·확인 절차를 그대로 적용한다.

같은 세션·문제의 다음 완료 측정은 직전 기록의 마지막 계획을 `previousPlan`으로 고정해 연결한다. 다음 결과를 본 뒤 세운 계획을 그 결과의 사전 예측으로 취급하지 않는다. 실패·중단 실행은 완료 측정 기록으로 등록하지 않는다.

- **장비 자료:** 같은 문제·순서·명령 목표·자료 출처인 경우 RMSE 전후값과 예상 방향의 일치 여부를 제시한다. 이는 기록된 목표의 비교이며 속도·부하·환경 등 모든 물리 조건이 동일함을 보증하지 않는다. 한 번의 감소로 원인·개선 효과를 확정하지 않는다. ‘비슷함’은 0.01 mm 표시값 기준이며 통계적 유의성 기준이 아니다.
- **목표나 출처 변경:** RMSE 증감만으로 개선을 판정하지 않는다. 기록된 변경과 근거를 교사가 함께 검토한다.
- **가상 자료:** 기존 고정 패턴으로 해석 절차만 연습한다. 반복 후에도 물리적 개선·원인 검증으로 표시하지 않는다.

새 측정 피드백 기록은 별도 브라우저 저장소에 백업하며 JSON으로 내려받는다. 이 신규 저장소와 `MathInquiry` 저장소는 개수 제한으로 조용히 삭제하지 않는다. 저장 한도 등에 실패하면 화면에 알리고 현재 메모리 기록을 내려받을 수 있게 한다. 브라우저 데이터 삭제·장치 변경에 대한 영구 보존은 보장하지 않는다. 기존 사각형 원시 측정·이벤트 저장소의 최대 100개 정책은 바꾸지 않는다. 연구자는 수업 종료 후 원시 기록과 피드백 기록을 함께 보관해야 한다.

## 프로포절에서 확인할 최소 연구 근거

아래는 이 프로토타입의 파일럿 점검 기준이다. 학위 심사 합격 기준이나 타당화된 평가도구를 대신하지 않는다.

| 확인할 학습 성과 | 필요한 활동·자료 | 현재 상태와 남은 확인 |
| --- | --- | --- |
| 문제를 수학으로 표현 | 실행 전 좌표·변화량·관계식·명령과 근거 | 콘텐츠·기록 구현. 실제 학생의 최초 수행 수집 필요 |
| 결과를 근거로 생각 수정 | 처음 예측, 관찰값, 수정 판단·설명 연결 | 콘텐츠·기록 구현. 설명의 타당성은 교사 평정 필요 |
| 지원 후 스스로 적용 | 새 조건의 첫 제출, 힌트 사용, 성공·중단 구분 | 활동·기록 구현. 연습 답의 기억과 새로운 조건 전이를 구분해 분석 필요 |
| 물리 피드백으로 재검증 | 장비 보고값, 사전 가설·확인 계획, 후속 측정 | 기록 연결 구현. 실제 장비 파일럿과 반복 자료 수집 필요 |
| 학습 효과·지원 효과 | 사전·사후 및 새 상황 수행, 관찰·면담, 조건별 지원 이력 | 앱 통과율만으로 검증 불가. 연구 설계·도구 타당화·학습자 자료 필요 |

파일럿에서는 (1) 기준·단위·수학적 표현의 정확성, (2) 관찰 증거와 설명의 연결, (3) 새 조건에서의 독립 적용을 각각 별도 평정한다. 서술형 예시 답안과 평가자 간 일치 기준을 먼저 마련하고 전문가 검토와 예비 적용으로 수정한다. 첫 제출 성공률, 피드백 후 수정 비율, 새 조건 첫 제출 성공률을 섞지 않는다. 어떤 지원을 얼마나 받았는지도 함께 해석한다.

프로포절의 7단계 순환에 대응하는 대표 활동과 피드백 기록을 구현한 상태다. 이것만으로 학생의 학습 효과, AI의 적응 지원, 실장비 정확도 또는 프로포절 통과가 입증되지는 않는다. AI·교사의 역할, 탐색적 적용과 효과 검증의 범위, 전문가 검토·파일럿·본 적용 계획을 연구문제와 일치시키는 작업이 남는다.

## 학생 설계와 새 조건 적용

App의 종합 픽앤플레이스는 고정 예제 실행에서 `PickPlaceDesignLesson`의 직접 설계로 바뀌었다. 2-2의 같은 운반을 절대·상대 두 방식으로 실행하는 활동은 유지한다. 종합과제에서는 각 구간에 절대·상대·혼합 명령을 사용할 수 있으며, 12단계 이내에서 여러 유효한 계획을 허용한다. 목표는 옆으로 운반할 때 주어진 최소 높이 유지, 내려놓기 직전 수직 하강 MoveL, 해제 후 수직 상승이다. 정해진 유일한 명령 목록과 비교하지 않는다.

- 계획과 높이 예측·근거는 실행 전에 저장한다. 처음부터 빈 좌표와 선택으로 시작하며 답을 대신 채우지 않는다.
- 각 시도는 명시된 출발 TCP에 배치한 뒤 시작한다. 상대좌표는 해당 이동 직전의 **실제 모델 FK 위치**에 더한다. 기존 FK/IK의 반올림을 유지하며 과제 위치·높이 판정에는 0.15 mm 허용차를 적용한다.
- 실행 가능한 잘못된 계획은 그대로 실행해 결과를 확인한다. 잘못된 흡착은 물체를 부착하지 않으며, 계산 불가 구간은 앞의 유효 구간까지만 실행한다. 중단·계산 불가를 성공으로 기록하지 않는다.
- 운반 높이는 물체를 잡고 있는 구간의 FK 표본으로 확인한다. 빈 흡착기의 해제 후 상승은 물체 최고 높이에서 제외한다. 주어진 경로 조건 확인이며 연속 충돌 검사의 보장이 아니다.
- 명령을 고치려면 수정할 관계와 근거를 저장하고 새 계획을 실행한다. 명령은 맞고 높이 예측만 틀리면 기존 실행 결과로 판단만 고칠 수 있다. 최초 예상과 후속 `predictionReviews`는 분리하며 불필요한 재실행을 요구하지 않는다.
- 결과 설명을 저장하면 위치·높이가 바뀐 두 번째 작업을 빈 계획에서 시작한다. 첫 성공·지원/수정 후 성공을 구분하며 설명의 질은 교사가 검토한다.

신규 `physical-ai-design-evidence-v1` 저장소는 조건, 학생 명령, 최초 예상·근거, 수정 근거, 힌트 사용, 결과 설명, 실행 상태·실행 중 적용한 FK 표본을 보관한다. 같은 계획을 다시 실행해도 별도 시도로 만들어 이전 완료 결과를 보존한다. 전체 계획의 계산 결과와 실제 재생된 표본은 별도 필드다. HOME·중지·목차 이동·장비 연결 전환은 현재 재생을 취소하고 중단 상태를 남긴다. 새로고침 후 기록은 내보낼 수 있으나 작업 진행을 자동 재개하지 않는다. 기존 장비 명령 경로는 변경하지 않는다.

## 학생에게 돌아가는 학습 정리

`MathInquiry` 단원에서는 최근 조건의 각 관계를 ‘실행·확인 전 / 다시 확인 필요 / 첫 예측 일치 / 피드백·수정 후 일치’로 구분해 보여준다. 종합과제에서는 첫 작업과 바뀐 작업의 계획·수정 기록을 구분한다. 이는 답·실행에 근거한 확인 상태이며 숙달도 점수나 학습 효과 판정이 아니다. 새 조건의 첫 답·힌트 사용 여부·자기 설명을 함께 봐야 한다. 전 단원 학습자 대시보드나 타당화된 수행평가를 완성했다는 뜻은 아니다.

기초수학의 단일 링크 100 mm 예시는 삼각비 성분을 익히기 위한 문제이고, 3장의 DT 모델은 링크 각각 175 mm와 기존 표시 오프셋을 사용한다. 기존 FK 계산·기초 개념 탭은 유지하며 문제 활동을 기본 진입으로 둔다. 기초 계산은 `dataSource: math`, 로봇 모델 실행은 `dataSource: dt`로 기록한다.


## 서술형 근거의 수학 검증과 수정 기록

`MathInquiry` 공통 활동은 최초 답안·근거를 보존하고 수학 관계에 대한 피드백을 제공한다. **기초수학 6개 문항**은 문항 조건 스냅샷(`reasoning`), 숫자 답, 설명을 함께 참고한다. 출발값·목표값·단위·계산 결과를 설명에 다시 적는 것을 통과 요건으로 삼지 않는다. 다른 공통 활동은 지원하는 산술식의 계산을 확인하며, 별도 폼을 사용하는 모든 서술 입력을 자동 채점하는 기능은 아니다.

- 예측: `예측·근거 저장`은 최초 응답을 보존한다. 수학 관계 확인 또는 필요한 DT 실행이 끝난 뒤 피드백을 생성한다. 실행 전 예측과 피드백 후 답을 구분한다.
- 간결한 근거: 숫자 답이 15라면 `60−45`, `60−45=15`, `45+15=60`, “목표 높이에서 현재 높이를 빼면 15가 나옵니다” 같은 표현을 확인한다. 숫자 입력란에 표시된 mm를 문장에 다시 쓰지 않아도 된다. 피타고라스 정리의 적용이나 성분별 삼각비를 말로 밝힌 경우도 문항과 숫자 답을 함께 검토한다.
- 명확한 오류: `60+45=15`의 계산 오류, 뺄셈 순서 반전, 입력한 숫자와 설명에 명시한 결론의 불일치는 계속 안내한다. 우연히 나온 다른 계산값을 문항의 최종 답으로 취급하지 않는다.
- 결과 해석: `purpose: reflection`일 때에는 해당 문항의 비교·해석 질문을 참고한다. “출발 높이가 높아져서 남은 상승량이 줄었습니다”, “수평 성분은 줄고 높이는 커집니다”처럼 질문에 맞는 설명을 확인하며 계산식을 다시 요구하지 않는다.
- 표시: 기본 화면에는 핵심 피드백을 하나 보여 주고, 아직 판단하기 어려우면 생각해 볼 질문 하나를 제시한다. 기준별 내용과 근거 인용은 `확인한 내용 보기` 안에 접어 둔다. 문항·입력값에서 가져온 정보는 `context`로 표시하며 학생이 직접 서술했다는 뜻의 `confirmed`와 구분한다.
- 판단 보류: 지원하지 않는 표현·부정/인용·다른 단위 변환을 오답이나 개념 미이해로 단정하지 않는다. 설명이 짧거나 의미를 자동 판단하지 못해도 저장 후 다음 조건으로 진행할 수 있다. 숫자 답의 확인과 비어 있지 않은 설명 저장은 유지한다. 설명이나 숫자 답을 편집한 경우에는 현재 답을 다시 저장해야 한다.
- 오류 후 진행: 명확한 오류가 있으면 수정 후 저장하거나 기존 `교사 검토용으로 남기고 계속`을 선택한다. 이 선택은 `teacherReviewRequested`로 남고 자동 정답·교사 검토 완료로 기록하지 않는다.
- 기록: 최초 `reason`은 덮어쓰지 않는다. `explanationReviews`는 원문·단계(initial/revision)·시각·runCount·당시 숫자 답·평가 버전·규칙 출처·항목별 상태를 누적한다. `reflections`에는 같은 자료와 `unresolved`를 저장한다. 진행 가능 여부와 확인/보류 판정은 별개이며, 보류 상태로 넘어간 답을 정답 수에 합산해서는 안 된다.
- 보존: 기존 JSON 내보내기·브라우저 백업·저장 실패 안내를 유지한다. `math-explanation-v1` 기록을 새 규칙으로 소급 판정하지 않는다. 새 평가에는 `version: math-explanation-v2`를 기록해 규칙 변경 전후를 구분한다. 교사 자동 알림이나 중앙 서버 전송은 없으며 필요한 경우 기록을 내려받아 전달한다.

이는 `provider: rule-based`인 제한된 수학 확인이다. 자연어에 대한 일부 명시적 관계를 지원하지만 자유로운 문장 의미 전체를 판정하는 외부 AI/LLM 채점은 아니다. 사칙연산·괄호·거듭제곱·제곱근·도 단위 sin/cos를 계산하며 임의 코드는 실행하지 않는다. 입력 길이·중첩·식 개수를 제한한다. **확인한 관계의 일치, 학습 진행, 개념 이해의 입증은 구분한다.** 평가도구로 사용하기 전에 실제 학생 표현을 수집하고 교사 평정과 비교하여 오판정·판단 보류·평정자 일치도를 점검해야 한다.
