# 공통 저속·설치 프로필 사용

- 새 준비 설정의 기본 속도는 **5%**, 웹 조절 범위는 **1~20%**입니다. 이는 컨트롤러의 속도 비율이며 TCP의 실제 mm/s 실측값이 아닙니다.
- 웹 상단의 공통 실장비 속도에서 **현재 적용**과 **변경 예정**을 구분합니다. 최신 정지 상태에서 별도로 승인하고, configure 성공 응답 전에는 적용 완료로 표시하지 않습니다. 실패·연결 끊김 시 적용 상태는 미확인입니다.
- 수동·과제·과제 시작점 이동은 같은 준비 설정을 사용합니다. 이 브리지는 매 MoveJ/MoveL/관절 한 칸 이동 직전에 승인된 SpeedFactor를 다시 설정하며, 속도 명령이 거부되면 이동 명령을 보내지 않습니다. 웹의 expectedSpeed가 서버 설정과 다르면 실행을 거절합니다.
- 기존 브리지를 쓰는 PC에는 새 다운로드의 소스를 반영해야 위 추가 보호가 적용됩니다. 교체는 로봇 정지 상태에서 운영자가 수행하고 연결·설치를 다시 확인하세요. 웹 수정만으로 이미 실행 중인 PC 브리지 소스가 바뀌지는 않습니다.
- 설치 프로필은 브라우저에 사람이 확인한 IP/PC 대상, User/Tool/TCP, IO, 작업 범위와 확인 시점을 저장합니다. 새 연결에서 자동 연결·체크·적용하지 않습니다. 저장 요약을 검토하고 **설치 및 주변 조건이 동일함을 확인하고 적용**을 명시적으로 승인하세요. 모의 프로필은 실제 장비 확인이 아닙니다.
- User/Tool/IO/범위 변경은 관련 확인을 해제합니다. 같은 활성 연결의 변경 없는 확인은 재사용하지만, 연결·오류·정지 불확실 상태에서는 재확인이 필요합니다. 속도 변경만으로 설치 체크 전체를 다시 요구하지 않습니다.
- 기본 범위 X200~350/Y-160~160/Z0~320/R-180~180은 입력 예시이며 현장 검증을 대신하지 않습니다. 제조사 최대 도달 범위를 직육면체 안전 범위로 확대하지 않습니다. 담당자는 User 원점, Tool/TCP 교정, 지그·바닥·장애물·배선 여유를 확인하고 검증된 프로필을 저장해야 합니다.
- 현재 TCP, 단계별 목표 및 시작점은 원시 좌표로 범위를 검사합니다. 화면에 0.00으로 보여도 원시 Z가 -0.0000001이면 Z 하한 0 밖이므로 차단합니다. 정확한 Z=0 등 경계는 실행 승인 전에 별도로 알립니다. 반올림, 도착 허용 오차 또는 작은 epsilon으로 범위를 완화하지 않습니다.
- 이 검사는 좌표/일부 관절 경로의 수치 검사입니다. 장애물·공구·배선·교정을 센서로 검증하거나 전체 이동 궤적의 무충돌을 인증하는 기능이 아닙니다. 매 실행 확인과 물리 비상정지는 계속 필요합니다.

# MG400 실습 PC 브리지 · 프로토콜 2

이 프로그램은 웹 수업과 **로봇 옆 PC** 사이의 연결 프로그램입니다.
기본값은 **모의 통신**입니다. Python 3.11 이상만 필요하며 pip 설치, API 키, Dobot SDK 설치는 필요 없습니다.
모의 값은 실측이 아니며, 실제 MG400에서의 호환성·동작·안전성은 아직 검증하지 않았습니다.

## 먼저: 장비 없는 가상 실습

콘텐츠는 처음부터 ‘가상 실습’으로 시작합니다. 인터넷 브라우저만 있으면 됩니다.
MG400, DobotStudio Pro, PC 브리지 없이 1~4장과 기존 7단계 수업을 실행할 수 있습니다.
4장에서 학생이 설계한 명령을 가상으로 실행하고 관찰·비교·수정합니다.
가상 실행 기록과 모의/실측 기록은 구분하여 보관합니다.

## 모의 연결을 확인하는 방법

1. 이 ZIP을 PC의 폴더에 풀고 터미널에서 해당 폴더로 이동합니다.
2. Python을 설치한 뒤 `python --version`으로 3.11 이상인지 확인합니다.
   Windows에서는 `py -3`을 `python` 대신 사용할 수 있습니다.
3. 웹 화면 ‘안내·연결’의 **이 앱 Origin**을 복사합니다. 주소 뒤의 `/` 및 경로를 넣지 않습니다.
4. 아래 명령의 `APP_ORIGIN`을 복사한 Origin으로 바꿉니다.

```
python server.py --mock --allow-origin APP_ORIGIN
```

5. ‘실제 로봇’ 모드를 선택하고 브리지 주소 `ws://127.0.0.1:8765`를 입력합니다.
   같은 PC의 브라우저를 사용합니다. 로봇 IP 칸에는 모의 테스트용 `192.168.1.6`을 입력합니다.
   **--mock에서는 이 IP로 네트워크 접속하지 않습니다.**
6. 연결합니다. 주황색 **모의 통신 · 실장비 아님** 표시를 확인합니다.
   연결 및 모드 선택은 이동·서보 활성화·흡착을 실행하지 않습니다.
7. 모의 시험에서는 6개 준비 항목을 모의 조건으로 확인하고 설정을 적용합니다.
   실제 현장에서 같은 항목을 확인했다는 뜻으로 사용하면 안 됩니다.
8. ‘서보 활성화’를 눌러 별도 확인하고, 명령 또는 4장의 같은 계획 실행을 별도로 승인합니다.
   TCP·관절·DI/DO·상태와 단계별 기록의 출처는 계속 **mock**입니다.
9. 검사: `python test_bridge.py`는 모의 통신·패킷·Origin·명령 차단을 검사합니다. 실제 장비에 접속하지 않습니다.

브라우저가 HTTPS 페이지에서 `ws://` 연결 또는 로컬 네트워크 접근을 차단하면 오류가 표시됩니다.
브라우저의 보안 설정을 끄지 마세요. 아래의 신뢰된 TLS 연결을 사용하거나 승인된 PC 관리 환경에서 확인합니다.

## 실제 장비 준비 — 현장 운영자 전용, 자동 실행 아님

이 버전의 실제 장비 경로는 **공식 문서 기준으로 작성했으며 실제 장비 시험 전**입니다.
이 프로젝트에서 실장비에 접속하거나 실제 명령을 전송한 적은 없습니다.
교사/장비 관리자가 장비 매뉴얼에 따라 현장에서 검증한 후에만 사용하세요.

### 확인할 조건

- **모델:** MG400. 6축 DOBOT 프로토콜과 혼용하지 않습니다. M1Pro는 같은 SDK 계열이지만 이 수업 브리지는 허용하지 않습니다.
- **펌웨어:** 공식 4축 Python SDK 기준 MG400 컨트롤러 V1.5.6.0 이상.
  피드백의 1440바이트 길이, 매직 값, MG400 모델 식별을 검사합니다. 이 검사는 모든 펌웨어의 호환성을 보증하지 않습니다.
  펌웨어 버전은 DobotStudio Pro/장비 관리자가 직접 확인합니다.
- **DobotStudio Pro:** 현장에서 네트워크·교정·TCP/IP 원격 제어 설정에 사용합니다.
  기본 가상 수업에는 필요하지 않습니다. 실제 운전에서는 TCP/IP secondary-development/control 모드를 설정해야 합니다.
- **네트워크:** 공식 SDK 예시는 MG400 **LAN1 = 192.168.1.6**입니다. 장비에서 바꾸었다면 확인된 IP를 사용합니다.
  PC는 같은 서브넷의 **다른 IP**를 사용하고 IP 충돌을 피합니다. 회사/학교 네트워크 관리자와 방화벽 범위를 확인합니다.
- **포트:** PC→로봇 TCP **29999**(dashboard), **30003**(motion), **30004**(feedback).
  웹 브라우저는 로봇 포트에 직접 접속하지 않습니다. 브라우저→PC 브리지 기본 포트는 **8765**입니다.
- **좌표계:** User/Tool을 현장에서 먼저 교정합니다. 수업 좌표, mm/deg 단위, 축 방향, 설치 방향 및 TCP를 대조합니다.
  화면 모델의 관절 표시 오프셋이나 가상 HOME을 실제 교정값으로 사용하지 않습니다.
  실제 feedback의 TCP와 DobotStudio 표시가 같은 User/Tool에서 일치하는지 직접 확인합니다.
  Tool/User 설정이 피드백에 반영되지 않으면 준비가 거부됩니다. 장비에서 해당 설정/제어 상태를 확인합니다.
- **공구:** 흡착기 TCP·공구 길이·하중·배선·전원·높이·R 방향을 확인합니다.
  로봇 포즈와 DO만으로 실제 물체의 집기/놓기 성공을 판정할 수 없습니다.
- **IO:** 흡착 DO 1~16, 필요시 별도의 해제 DO, 진공 확인 DI, 출력 극성을 장비 도면에 맞춥니다.
  실제 배선이 없으면 번호를 추정하지 마세요. 문서 기준 bit0=DI/DO1입니다.
  해제 DO를 지정하면 흡착 OFF 때 해제 출력이 켜져 유지되고 다음 흡착 ON 때 꺼집니다.
  **시간 제한 펄스가 필요한 장치는 이 옵션을 사용하지 마세요. 현재 버전에는 펄스 제어가 없습니다.**
- **작업 공간:** 작업대·물체·지그·툴·사람·전체 로봇 팔의 공간 및 각 이동 경로를 직접 확인합니다.
  UI 초기 범위는 예시이지 장비의 허용 범위가 아닙니다. 검증된 최소/최대 X/Y/Z/R로 바꿉니다.
  MoveJ는 TCP 직선 경로가 아닙니다. 이 프로그램은 전체 팔의 물리 충돌이나 힘을 측정하지 않습니다.
  가상 선검사는 안전 인증/위험성 평가를 대체하지 않습니다.

### HTTPS / WSS

HTTPS 웹 앱에서 다른 PC/LAN의 `ws://` 주소는 일반적으로 차단됩니다.
권장 경로는 학교/회사에서 신뢰하는 인증서를 이용한 **wss://PC_HOST:8765/**입니다.
인증서 SAN에 PC_HOST가 포함되고 브라우저가 해당 발급자를 신뢰해야 합니다.
신뢰되지 않은 자체 서명 인증서는 연결 실패가 정상입니다. 검증을 끄지 마세요.

```
python server.py --mock --host 0.0.0.0 --cert certificate.pem --key private-key.pem --allow-origin APP_ORIGIN
```

먼저 **TLS도 모의 모드에서** 확인합니다.
개인키는 해당 PC에만 보관하고 웹 앱/채팅/ZIP에 올리지 않습니다.
PC 방화벽은 승인된 수업 PC만 허용합니다. 인터넷 포트포워딩 및 공개 터널로 로봇 제어를 노출하지 마세요.
TLS 없는 외부/LAN 바인딩은 프로그램이 거부합니다. Origin은 정확히 일치해야 하고 한 브라우저만 제어합니다.
Origin 검사는 별도의 사용자 인증을 대체하지 않으므로 공유 PC·공유 Origin 운영 권한을 현장에서 관리하세요.

### 현장 승인 후의 연결

현장 운영자가 위험성 평가와 준비를 마친 후에만 다음 옵션으로 프로그램을 시작합니다.
이 명령은 **현재 Replit 환경에서 실행하지 마세요.**

```
python server.py --allow-hardware --host 0.0.0.0 --cert certificate.pem --key private-key.pem --allow-origin APP_ORIGIN
```

브리지 시작 자체는 로봇에 접속하지 않습니다. 웹의 ‘연결’을 누르면 지정한 로봇에 읽기 연결을 엽니다.
연결은 EnableRobot/이동/흡착/알람해제를 보내지 않습니다.
설정 적용은 User/Tool/저속 비율 설정만 하며, 이동과 흡착을 실행하지 않습니다.
6개 준비 확인 → 준비 적용 → 별도 서보 활성화 승인 → 각각의 실제 실행 승인 순서입니다.
실측이 없거나 오래됐거나 오류 상태이면 실행을 차단하고 가상값으로 대신하지 않습니다.

## 같은 계획, 출처가 다른 관찰

4장의 가상 기록에서 ‘같은 계획을 실제 로봇에서 사용’을 선택하면 명령·예상값을 그대로 가져옵니다.
가상 기록은 덮어쓰지 않습니다. 실제 실행 전에 **예측 전용 가상 선검사**와 현장 확인이 필요합니다.
상대 계획은 같은 시작 위치를 먼저 확인하며, 매 단계 새로 측정된 TCP에서 Δ를 더합니다.
명령 ACK만으로 완료로 판단하지 않습니다. 새 측정값으로 위치/R/IO 및 정지를 확인합니다.
실측 기록에는 목표·예측·실측 TCP·관절·DI/DO·상태·출처가 있고, 가상 기록과 구분하여 내려받습니다.
**실제 물체 상태는 ‘확인 안 됨’**입니다. 눈으로 확인한 관찰을 적고 교사 검토를 받으세요.
화면 하단 TCP X/Y/Z/R ± 버튼은 실측 기준 MoveL 한 칸 이동, 관절 J1/J2/J3/J4 ± 버튼은 실측 관절각 기준 JointMovJ 한 칸 이동입니다. Step Value는 TCP mm, R/관절 deg입니다. 길게 눌러도 반복하지 않습니다. 임의의 전체 관절 목표(FK 학습 명령)는 계속 차단합니다.

관절 버튼에는 v2.1 브리지가 필요합니다. 기존 server.py를 Ctrl+C로 종료하고 새 ZIP으로 교체한 뒤 같은 실행 명령으로 재시작하세요. 시작 로그에 `v2.1 (TCP + joint steps)`가 표시됩니다.

관절 경로는 제조사 PositiveSolution으로 User/Tool을 적용해 1도 이하 간격으로 확인한 뒤 전송합니다. 관절 범위 J1 ±160°, J2 -25~85°, J3 -25~105°, J4는 구형 모델을 고려해 ±180°로 제한합니다. 이동 중 TCP 작업 범위도 감시합니다. 샘플링 검사는 충돌 판정이나 연속 경로의 안전 보장이 아니므로 설정한 작업 범위의 장애물 확인이 필요합니다. FK 응답을 해석할 수 없으면 이동하지 않습니다.

연결만 하고 버튼을 누르면 아직 준비되지 않은 이유가 하단에 표시됩니다. 4번 준비 설정 적용 후 5번 서보 활성 상태를 확인하세요. 실제 TCP 현재 위치가 설정 범위 안에 있어야 합니다. 외부 DobotStudio 조그는 실측 패널만 갱신하며 가상 모델은 콘텐츠 명령 완료 시 갱신됩니다.
HOME은 가상 화면의 초기화이며 실제 로봇 복귀 명령이 아닙니다.
확장 공정은 기존대로 보존되지만 실제 제어 대상이 아니며 가상 실습에서만 사용합니다.

## 중단과 오류

- **화면 중단 요청 ≠ 물리 비상정지.** ResetRobot()으로 소프트웨어 정지를 요청하지만 네트워크가 끊기면 전달되지 않을 수 있습니다.
- 위험하면 먼저 장비의 **물리 비상정지 버튼**을 사용합니다.
- 중단·단절·화면 이동은 다음 명령을 차단하고 실측된 실행 구간만 남깁니다.
- 흡착 OFF·DisableRobot·ClearError·계속 운전은 중단/재연결 때 자동 호출하지 않습니다. 작업물이 떨어질 수 있기 때문입니다.
- 실제 정지를 현장에서 확인한 후 화면에서 정지 확인, 재연결 및 준비 확인을 다시 합니다.
  에러 원인은 현장에서 해결해야 하며 웹 버튼이 장비 알람을 지우지 않습니다.
- 실패시: 펌웨어/모델 → 로봇 LAN/IP → TCP/IP 제어 모드/포트 → Origin → TLS/PC 주소 → 신선한 피드백 → User/Tool → IO/작업 범위 순으로 확인합니다.
  모의 통신이 된다는 것은 물리 장비의 호환성이나 안전성을 입증하지 않습니다.
