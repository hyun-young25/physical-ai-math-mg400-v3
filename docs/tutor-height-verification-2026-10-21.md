## 동작 변경

- 데스크톱의 최대 580px 제한을 없애고 실제 상단 메뉴 아래 12px부터 하단 16px까지 사용한다.
- 창 크기, 상단 헤더 높이, 보이는 뷰포트의 높이/위치 변경에 따라 갱신한다.
- 모바일은 기존 하단 도킹을 유지하며 일반적으로 화면 높이의 72%까지 사용한다.
  키보드가 열리면 실제 가시 영역 안으로 높이를 제한하고 키보드 위로 올린다.
- 제목·최소화·닫기와 입력창·전송은 스크롤 영역 밖에 둔다.
  긴 대화는 대화 영역에서, 높이가 부족한 안내·상태·추천 질문은 보조 내부 영역에서 스크롤한다.
- 아주 짧은 키보드/가로 화면에서는 상단 학습 메뉴 일부를 덮을 수 있다.
  이때 닫기를 가리지 않도록 학생 바보다 위에 표시하되 기존 최종 실행 확인창보다 아래에 둔다.
  개발 미리보기 배너의 공간은 앱의 실제 위치를 측정해 제외한다.
- 튜터가 320px 이하일 때만 입력과 전송을 한 줄로 줄인다.
  글자 수 안내는 보조 기술에 계속 연결되어 있고 길이 검사도 유지한다.
- 데스크톱 폭 336px, 색상, 글꼴 종류를 유지한다.
  모바일 입력 글자 크기만 16px로 조정하여 iOS의 입력 시 자동 확대를 방지한다.

## 증거 및 한계

- 재실행 가능한 검사: `scripts/verify-tutor-height.cjs`.
- 결과: `generated-artifacts/tutor-height.json`.
- 각 상태 화면: `generated-artifacts/tutor-height-*.png`.
  이 폴더는 기존처럼 Git/게시 대상에서 제외된다.
- 기본 스크린샷 도구는 비로그인 입장 화면만 확인했다.
  튜터 화면은 별도 Playwright의 합성 학생 입장으로 확인하고 저장한 스크린샷을 검토했다.
- 실제 학생 인증/DB 저장/GPT 성공이나 실제 장비는 이번 검증 대상이 아니다.
- 키보드 검사는 VisualViewport 이벤트와 창 높이 변경을 이용한 모의 검사다.
  실제 iPhone/Android의 소프트 키보드·브라우저별 동작은 직접 검증하지 않았다.
- 전체 기존 단위 검사 모음은 재실행하지 않았으며, 기존 전체 검사 통과를 주장하지 않는다.
